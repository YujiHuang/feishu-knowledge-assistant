## 配置项全表

`config.yaml`（从 `config.example.yaml` 复制）。改配置多数即时生效，无需重启。

| 配置 | 说明 |
|---|---|
| `server.port` | 默认 8787。**改了必须同步改飞书后台的重定向 URL**，两边端口不一致会授权失败 |
| `llm.base_url` | 任意 OpenAI 兼容网关（`/chat/completions`），填到 `/v1` 为止 |
| `llm.model` | 模型名会换代，不确定就跑 `python tests/check_gateway.py` 看当前 key 下实际可用的列表 |
| `llm.api_key` | 建议留空，改用环境变量或钥匙串（见下节） |
| `embedding.provider` | 默认 `local`（本地 bge-small-zh，不花钱）。网关提供 `/embeddings` 时可改 `openai` |
| `retrieval.vector_top_k` / `keyword_top_k` / `final_top_k` | 向量召回 / BM25 召回 / RRF 融合后送进提示词的片段数 |
| `retrieval.history_rounds` | 追问时带进提示词的历史轮数，默认 2。每轮都要重发一遍问答，是纯 token 成本；额度紧就调到 1 或 0 |
| `retrieval.web_fallback_threshold` | 知识库 top1 相似度低于此值触发联网兜底，默认 0.45。联网太频繁就调低，该查的没查就调高 |
| `retrieval.recency_weight` | 时效加权强度（0 关闭）。最终得分 = 相关度 ×（1 + 权重 × exp(-文档年龄 / 半衰期)），同等相关度下最近编辑的优先 |
| `retrieval.recency_half_life_days` | 时效衰减半衰期，默认 90 天 |
| `web_search.api_key` | [Tavily](https://tavily.com) 的 key，留空则禁用联网兜底 |
| `sync.wiki_space_allowlist` | 只同步这些知识库空间的 space_id。留空 `[]` = 全部可见空间（不推荐，语料会很杂） |
| `sync.include_my_space` | 是否同步个人云盘，默认 `false`。开了语料会明显变杂 |
| `sync.auto_sync_minutes` | 定时自动同步间隔，默认 60，`0` 表示只手动 |
| `sync.exclude_tokens` | 排除清单：文档 / 文件夹 / wiki 节点 token（取链接里那串） |
| `sync.exclude_title_prefixes` | 按标题前缀排除，默认排掉妙记的「文字记录：」「智能纪要：」 |
| `sync.exclude_title_keywords` | 按标题关键词排除非正式文档，默认：日会 / 周会 / 例会 / 站会 / 晨会 / 双周会 |
| `sync.extra_doc_urls` | 枚举不到的「别人单独分享给你」的文档，手动贴链接补充（等价于网页上的「添加」框） |
| `storage.data_dir` | 索引、飞书凭证、同步状态的落地目录，默认 `~/.knowledge-assistant` |
| `bot.name` | 只 @ 机器人、不带问题时自我介绍用的名字 |
| `bot.projects` | 机器人可检索的项目（知识库一级目录）白名单，`[]` = 全部开放 |

**项目归类规则**：知识库里的一级目录名即项目名，顶层散文档归到空间名下。目录改名或移动，下次同步会自动跟上——变更签名里含 project / title / url，不是只看编辑时间。

## 密钥不落盘：环境变量覆盖机制

任意配置项都能用环境变量覆盖，命名规则是 `KA_` + 配置路径大写下划线连接：

```
llm.api_key        → KA_LLM_API_KEY
web_search.api_key → KA_WEB_SEARCH_API_KEY
```

**环境变量优先级高于 `config.yaml`**，空字符串按「没设」处理，YAML 里的 `null` 回落到代码默认值。另外认几个习惯命名：`DEEPSEEK_API_KEY`、`OPENAI_API_KEY`（都映射到 `llm.api_key`）、`TAVILY_API_KEY`（映射到 `web_search.api_key`）。

只适合密钥、模型名这类**字符串**配置——环境变量取到的一定是字符串，不要用它覆盖 `temperature`、`top_k` 等数值项。

### start.sh 做了什么

`./start.sh` 按「环境变量 → macOS 钥匙串（服务名 `knowledge-assistant-llm`）→ 当场询问」的顺序取 key，然后 export 给 `python -m app.main`。第一次输入后它会问要不要存进钥匙串，存了以后就不用再输：

```bash
security find-generic-password -s knowledge-assistant-llm -w   # 看当前存的
security delete-generic-password -s knowledge-assistant-llm    # 删掉
```

启动后终端会打印一行 `LLM key 来源：…`，先确认这行正常再去提问。`./start.sh bot` 不需要 key——机器人不直接调模型，它 POST 主服务的 `/api/ask`。

### 想手动 export

**zsh 和 bash 的 `read` 语法不兼容**，macOS 默认是 zsh：

```bash
# zsh（macOS 默认）：提示语写在变量名后面的 ? 里
read -rs "DEEPSEEK_API_KEY?API Key: " && export DEEPSEEK_API_KEY && echo
# bash：提示语用 -p
read -rsp "API Key: " DEEPSEEK_API_KEY && export DEEPSEEK_API_KEY && echo
```

给 zsh 用 `-p` 会报 `no coprocess`。`-s` 不回显（粘贴时屏幕上没有任何字符，是正常的），整行也不会把 key 留进 shell 历史，key 只活在这个终端会话里。确认变量进去了：`echo ${#DEEPSEEK_API_KEY}`，它只打印长度不打印内容。

注意 **`app.main` 和 `check_gateway.py` 必须在同一个 export 过的终端里启动**。项目里所有脚本都用 `#!/usr/bin/env bash`，就是为了绕开这个 shell 差异。

## 引用定位是怎么做的

回答里每个序号 `[n]` 都是可点击的定位链接，点开会滚动到原文对应位置。做法：

1. **入库时埋锚点**。解析文档时，每一行正文都带上它在飞书里的块 ID（`block_id`），表格的每一条记录带上 `app:table:record:view`。锚点以 `\x00` 标记附在行尾，切块时提取出来。
2. **一个片段保留全部行锚点**。检索片段最长 600 字、可能横跨十几行，所以片段不是只存首行锚点，而是把**所有**行锚点及其字符偏移一起存进 LanceDB 的 `anchors` 列（JSON）。早期只存首行锚点，导致引用片段中后段的内容时链接跳到片段开头。
3. **回答生成后再定位**。用「序号紧邻的那句话」与片段内各行做加权匹配：数字权重 4 分 > 英文词 2.5 分 > 汉字二元组 1 分；匹配前剔除 `[n]` 本身，避免序号数字污染打分。
4. **证据不足就退回**。总分低于 `max(4, 0.25 × 总权重)` 时退回片段首行锚点，绝不乱跳。

切块重叠区（`CHUNK_OVERLAP=100`）会带来一个陷阱：重叠部分属于上一个片段，命中它会取到上一片段的锚点。所以 `_window` 返回 `(片段, 重叠长度)`，`_pick_anchor` 跳过重叠区。

**链接形式**：文档类用块锚点（docx 和 wiki 都实测稳定）；多维表格行统一用 `/base/` 直链的记录深链（带 `view` 参数——wiki 壳的深链实测不稳定，已弃用）；电子表格只能定位到工作表级。

**改了解析或切块逻辑，把 `app/feishu/sync.py` 的 `PARSER_VERSION` +1**，下次同步会自动全量重建索引。启动时提示「检测到旧版索引结构，已清空索引」就是这个机制在生效。

**飞书卡片不渲染 `#` 标题语法**，所以提示词里明确禁用，机器人侧还有正则兜底把 `##` 转成加粗；引用序号用 `[n]` 而不是 `【n】`。

## 能力边界的细节

- **能入库**：新版文档（docx，含内嵌多维表格 / 电子表格）、独立多维表格（`/base/` 与 wiki 节点）、电子表格（`/sheets/` 与 wiki 节点，首行视为表头按行展开）。
- **不支持**：旧版文档、思维笔记、文件附件正文。
- **表格行数截断**：多维表格 / 电子表格每表最多 1000 行。
- **附件**：走 `/api/media` 代理（含 `bitablePerm` extra 映射）。机器人会把本地 `/api/media/...` 路径替换成「附件请在来源文档中查看」——那是本机路径，发给别人没有意义，也不该外泄。

## 进程与代码结构

单仓库共享核心，多入口进程：

```
app/main.py      FastAPI 主服务：网页界面 + /api/ask + 授权回调 + 同步触发
app/bot.py       飞书机器人：lark-oapi 长连接收消息，POST 主服务的 /api/ask
app/config.py    配置加载 + 环境变量覆盖
app/feishu/      auth（OAuth）client（API 封装）sync（同步管线、PARSER_VERSION）
app/index/       chunker（切块埋锚点）embedder（fastembed）store（LanceDB）
app/rag/         retriever（向量 + BM25 RRF）answer（提示词与引用定位）websearch（Tavily）
app/web/         单文件前端
```

机器人复用主服务的问答能力，所以它必须在主服务已经在跑的前提下启动。机器人侧有按 `chat_id` 的多轮记忆（`deque maxlen=4`）、敲键盘表情（答案吐出即撤销）、占位卡片原地 patch。

## 回归测试

改完代码跑一遍：

```bash
cd ~/knowledge-assistant
python tests/test_anchor.py         # 切块、锚点归属、卡片文本渲染
python tests/test_locate.py         # 序号 → 精确行定位（含表格记录深链）
python tests/test_store_anchors.py  # LanceDB 落盘读回与旧索引迁移
python tests/test_history.py        # 历史轮数配置项（token 成本）
python tests/test_config_env.py     # 环境变量覆盖配置（密钥不落盘）
```

换网关、换模型、或者报错怀疑是网关问题时，先跑连通性自检（读 `config.yaml` + 环境变量，逐层给结论，包括列出当前 key 下实际可用的模型名）：

```bash
python tests/check_gateway.py
```

## 故障排查

| 现象 | 处理 |
|---|---|
| 授权页报 20027 | 某个 scope 没在后台开通，或改完权限没发布新版本 |
| 换 token 报 20010 | 应用可用范围不含你，去「应用发布」检查 |
| 同步大量报错 1770032 | 正常：枚举到了你无阅读权限的文档，会跳过 |
| 提问报「登录已过期」 | 重新点「连接飞书」（refresh_token 有效期到了） |
| 首次启动卡在下载模型，报 `CAS Client Error` / `File reconstruction error` | HuggingFace Xet 后端不稳，代码已默认 `HF_HUB_DISABLE_XET=1`，重跑即可 |
| 模型下载超时 / 被墙 | 先 `export HF_ENDPOINT=https://hf-mirror.com` 再启动 |
| 多次中断后报模型文件损坏 | 删缓存重下：`rm -rf ~/.cache/huggingface` |
| 网关调用失败 | 先跑 `python tests/check_gateway.py`，它会逐层告诉你是连不通、key 无效、模型名不存在还是没额度 |
| 报 401 / `Authentication Fails` | key 没传进去。多半是换了终端窗口忘了 export，或者 `config.yaml` 的 `api_key` 空着又没设环境变量——`check_gateway.py` 会打印 key 的来源 |
| 报 402 / `Budget pool quota has been exhausted` | 额度池耗尽。共享额度的网关要注意：同一机构的多个网关地址可能共用一个预算池，光换 `base_url` 不解决，得换 key 或加额度 |
| 报模型不存在 | 模型名换代了。跑 `check_gateway.py` 看当前 key 下实际可用的列表，别照文档或记忆里的旧名字填 |
| 群里 @ 机器人没反应 | 按顺序查：① `./start.sh bot` 那个终端还活着吗（它跟主服务是两个进程）；② @ 一次看终端有没有 `[收到]` 那行；③ 没有这行说明事件没推过来，多半缺权限 `im:message.group_at_msg:readonly`，单聊不通则是缺 `im:message.p2p_msg:readonly`；④ 加完权限**必须创建新版本并发布**才生效；⑤ 有 `[收到]` 但没回复，看终端 `⚠️ 回复失败 code=` |
| 启动时提示「检测到旧版索引结构，已清空索引」 | 正常：索引结构升级了，点一次「同步知识库」全量重建 |
| 序号点开定位不准 | 先确认已用新版全量同步过；表格里同一行内容重复度高时可能落到相邻记录 |
| 机器人回答出现 `##` 等裸符号 | 主服务和机器人都要重启（提示词与卡片渲染分别在这两个进程里） |
| 端口被占 / 授权跳回失败 | `config.yaml` 的 `server.port` 和飞书后台重定向 URL 必须一致 |
